# Pocketa｜日常收支

Pocketa 是繁體中文個人記帳 Web App，協助記錄日常支出、收入與每月固定收支，並整理每月及年度結餘。介面採深藍至白色漸層、黑色文字與四頁式底部導覽列，以新臺幣（TWD）顯示金額，記帳日期採臺灣時區（Asia/Taipei）。

- [開啟 Pocketa](https://a5029751.github.io/blue-ledger/)
- [GitHub 原始碼](https://github.com/a5029751/blue-ledger)
- 目前發布版本：**v2.2.0（build 18）**
- 文件整理日期：**2026-11-11**

目前交付形式是部署於 GitHub Pages 的網頁／PWA，可在支援的瀏覽器加入主畫面，以 App 式介面使用；並非 Apple 簽署的 IPA 安裝檔。

## 外幣記帳與 API 匯率

預設幣別為新臺幣（TWD）；一般／固定收入與支出均可選擇 19 種外幣。月度與年度統計統一以台幣加總。新增收支 → 選幣別 → 自動取得 API 報價 → 核對或修改匯率 → 輸入原幣金額 → 確認換算台幣 → 儲存。第四頁提供不寫入帳本的換算試算。

- API：`https://api.exchangerate.dev/v1/rate/{currency}-twd`。直接瀏覽器讀取，免帳號、免金鑰，不新增後端。僅送出幣別組合，不送出帳目、金額或備註。
- **免費行情延遲約 15 分鐘，不是無延遲即時行情，也不是台銀現金／即期成交價。** 每次選外幣會取得報價；可按「更新匯率」。同幣別 60 秒內使用記憶體快取，按更新可重新請求。無背景輪詢。匿名限制依供應商規定（目前每分鐘 10 次、每小時 100 次／IP）；429、斷線、逾時或資料不完整時顯示錯誤，可手動填寫，不冒用其他來源。
- 顯示報價觀測時間（臺灣時區）、延遲與 API 過期／休市標記。API `source`、市場狀態與觀測時間隨帳目保存。參考報價非成交證明，應核對實際交易匯率；未啟用付費服務或串流。
- **歷史日期不自動套用歷史行情**。新增歷史帳目取得的是當前可用參考報價，請手動填寫該筆實際匯率。歷史紀錄不因行情刷新而重估。
- **固定規則採儲存時固定匯率**，補建亦使用該匯率；不聲稱每月自動取得當日成交價。可編輯規則調整未來匯率，既有紀錄保留原值。
- BigInt 有理數換算，台幣入帳四捨五入至分；原幣金額及使用的匯率完整保留，不受縮寫影響。小於台幣 0.01 元或超過支援範圍時拒絕儲存。
- JSON 備份含原幣、原幣金額、匯率、來源與時間。含外幣時使用 schema 3，仍可讀取 schema 1/2 台幣帳本；舊版 App 不支援 schema 3，請勿降版編輯。
- CSV 在原欄位後追加原幣、原幣金額、匯率、種類、時間與來源。畫面外幣明細附來源連結。

[Rates by exchangerate.dev](https://exchangerate.dev) · [官方 API 文件與限制](https://exchangerate.dev/docs/api-reference)。原台銀方案已依使用者要求改為此 API；介面不再提供台銀匯入或銀行買賣價選項。

新增檔案：`src/fx.js`（精確換算與驗證）、`src/fx-api.js`（API、逾時與快取）、`src/FxFields.jsx`（記帳欄位）、`src/FxSettings.jsx`（試算）、`tests/fx*.test.mjs`（換算、備份與 API 測試）。

## 操作流程

### 1. 開始使用

1. 開啟 [Pocketa](https://a5029751.github.io/blue-ledger/)。
2. 用底部導覽列切換四個分頁。
3. 第一次使用會看到空白帳本；可直接新增收支，或到第四頁選擇「查看範例帳本」。
4. 範例模式不會寫入個人帳本；使用「回到我的帳本」或「結束示範模式」離開。

手機瀏覽器支援時，可透過分享選單或瀏覽器選單的「加入主畫面」開啟。首次完整載入後提供離線使用；安裝選項及離線能力依瀏覽器而異。

### 2. 新增與管理日常收支

1. 進入第二頁「收支記帳」，按「新增支出」或「新增收入」。
2. 填寫金額、分類、日期，視需要填寫項目名稱、付款方式或備註。
3. 按「儲存紀錄」，總覽與統計會隨之更新。
4. 在收支明細按「編輯」可修改或刪除該筆紀錄。
5. 透過月份、類型、分類、搜尋欄或分類 NAV 尋找紀錄；頁面會顯示篩選後的收入、支出與結餘。

實際收支不接受未來日期；每月預定項目請使用固定收支。

金額已取消原本 999,999,999 元上限。目前最多支援 1000 位整數及兩位小數，可輸入完整數字或縮寫，亦相容舊版小寫 k/m/b/t/q 與 e 輸入。實際金額不足一分會被拒絕。

顯示依英文短尺度（short scale）處理，K/M/B/T 採英文 compact number 格式；千兆以上沒有全球統一的金融縮寫標準，本專案以以下明列代號表示英文大數名稱，避免與 SI 前綴混淆。

| 代號 | 英文名稱 | 數值 |
| --- | --- | --- |
| K | thousand | 10³（千） |
| M | million | 10⁶（百萬） |
| B | billion | 10⁹（十億） |
| T | trillion | 10¹²（兆） |
| Qa | quadrillion | 10¹⁵（千兆）；舊版 q 的數值未變，顯示更正為 Qa |
| Qi | quintillion | 10¹⁸ |
| Sx | sextillion | 10²¹ |
| Sp | septillion | 10²⁴ |
| Oc | octillion | 10²⁷ |
| No | nonillion | 10³⁰ |
| Dc | decillion | 10³³ |

資料依據：[Unicode 英文數字格式](https://www.unicode.org/cldr/cldr-aux/charts/28/verify/numbers/en.html)、[NASA 英文大數名稱表](https://imagine.gsfc.nasa.gov/educators/gammaraybursts/starchild/page10.html)、[Wolfram 大數名稱](https://mathworld.wolfram.com/Number.html)。Qa 等代號為本專案明定的英文短尺度延伸代號，不宣稱是 ISO 或 SI 正式符號。

例如 `12200 → 12.2K`、`12345.67 → 12.35K`、`999999 → 1M`。縮寫顯示時四捨五入至最多兩位小數，省略尾端零；999.999 等接近下一級的數值可進位換單位。

10³⁶ 以上使用工程記號，例如 `1.235×10^36 → 1.24×10^36`。輸入過程提供縮寫預覽，離開欄位後顯示縮寫；重新點入可查看完整原值。顯示的小數位限制不會改寫原始金額，實際儲存、加總、JSON 與 CSV 仍保留完整精度。

### 3. 設定每月固定收入與支出

1. 在第二頁按「固定收入」或「固定支出」。
2. 輸入金額、分類、每月記帳日、項目名稱及開始日期；結束日期可留空。新增固定收入的項目名稱為選填，未填或僅填空白時，儲存後自動使用「每月薪資」；自行填寫則保留輸入名稱。新增固定支出仍須填寫項目名稱。
3. 儲存規則。若開始日期在過去，系統會補建截至今天已到期的項目。
4. 在「固定收支」頁籤管理規則，可編輯、暫停、恢復或結束。
5. 回到第一頁查看本月未到期項目，並自行核對銀行實際入扣款。

### 4. 查看當月與年度結果

1. 第一頁點「當月份存款」，在彈出視窗選擇年份及月份，再按「套用月份」查看該月收入、支出與結餘。原先首頁右上角的月份控制已合併至存款卡片，第二頁仍使用原本的月份選擇器與前後月按鈕。點「總收入」展開／收合「最近收支」，點「總支出」展開／收合「本月待入帳」。兩區預設收合，可獨立或同時展開；本次開啟期間切換分頁、月份仍保留開關狀態，重新載入後回到收合。展開保留原卡片樣式與內容，最近收支仍包含收入與支出，待入帳仍包含固定收入與固定支出。
2. 第三頁點選年度標題，展開或收合該年度表格。
3. 查看各月份的總收入、總支出及結餘，最下方為年度合計。
4. 點選月份可切換至該月收支明細；沒有紀錄的月份顯示「—」。

計算方式：**當月結餘＝當月已記錄收入－當月已記錄支出**；年度結餘為該年度已記錄收支的差額。畫面中的「當月份存款」指當月結餘，不是銀行餘額，也不包含期初存款。

### 5. 管理分類

1. 進入第四頁「資料與設定」，按「分類管理」。
2. 選擇收入或支出類型，輸入分類名稱並新增。
3. 既有分類可改名或封存；封存不會刪除歷史帳目，也可恢復。
4. 若分類仍被未結束的固定規則使用，須先調整或結束該規則才能封存。

### 6. 備份、匯出與還原

| 操作 | 步驟與用途 |
| --- | --- |
| 完整備份 | 第四頁 →「下載完整備份（含固定規則）」，保存 JSON 檔案，適合移轉及完整還原。 |
| CSV 匯出 | 第四頁 →「匯出全部收支 CSV」，供試算表查看收支；不包含完整固定規則，不能用來還原帳本。 |
| 還原 | 建議先備份現有帳本，再選「從備份還原」，選取 JSON 檔並確認取代目前帳本。 |
| 資料救援 | 若資料讀取失敗，系統停止寫入並提供原始資料下載，再從有效備份還原。 |

更換裝置、瀏覽器或網站來源時，先在原處下載 JSON，再到新處還原。舊 Sites 網址與目前 GitHub Pages 的資料不會自動移轉。備份含個人財務內容，請妥善保存。

### 7. 更新版本

1. 連上網路，進入第四頁「資料與設定」。
2. 查看目前版本與更新說明，按「檢查並更新」。
3. 已是最新版時顯示提示；有新版時會確認新版首頁已發布，再自動重新開啟。
4. 更新後返回第四頁並顯示結果，已儲存帳目與固定規則會保留。
5. 網路異常或新版尚在發布時會提示稍後重試，不需清除瀏覽器資料。

示範模式須先結束才能更新。更新按鈕用於取得已發布版本，並不會自行修改程式或發布尚未完成的功能。

## 資料保存與功能範圍

- 帳目保存在目前網站來源下的瀏覽器 `localStorage`，沿用儲存鍵 `blue-ledger-v1`。既有 version 1 備份仍可讀取；首次儲存需要字串表示的大額金額時，帳本升級為 version 2，保留舊紀錄。version 2 備份請使用 v2.1.0 或更新版還原，舊版無法讀取此格式。JSON 與 CSV 保存完整金額；試算表查看超大數字時請以文字欄匯入，以免試算表自行改寫精度。
- 沒有帳號登入、跨裝置同步或雲端帳本；GitHub 儲存原始碼，不接收使用者帳目。
- 同一網站來源的網址參數或 `#settings` 變化不會建立新帳本；不同網站來源、瀏覽器或裝置則彼此獨立。
- 清除網站資料或使用瀏覽器清理功能可能移除帳本；儲存空間也有上限，請定期下載完整備份。
- 固定收支是「自動建立記帳紀錄」，不會執行銀行扣款、轉帳或確認實際收款。
- 關閉 App 時不保證背景執行，到期紀錄會在下次開啟或回到前景時補建。
- 尚未提供原生 IPA、App Store 上架或銀行串接。

開發時修改 `src/`、根目錄入口與 `public/`，再建置產生 `dist/`，請勿直接修改產物。`artifacts/`、壓縮檔及 `node_modules/` 不納入 Git。`.openai/hosting.json` 保留先前託管設定，不是目前 GitHub Pages 的發布入口。

## 本機啟動與測試

需要 Node.js **20.19+ 或 22.12+**；本次以 Node.js 24 驗證。建議使用 pnpm，依照鎖定檔安裝：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

開啟 [本機開發預覽](http://127.0.0.1:4173/)。也可使用 `npm install`、`npm run dev`，但可重現的套件版本以 `pnpm-lock.yaml` 為準。

```sh
pnpm test
pnpm build
pnpm preview
```

`pnpm test` 執行 23 項記帳核心、更新、帳本儲存及大額金額測試；`pnpm build` 建置正式靜態檔案，檢查版本一致性並自動產生版本檔與 Service Worker；`pnpm preview` 於同一網址提供正式 `dist/`。開發伺服器與正式預覽請分開執行，避免同時占用 4173 埠。

首次安裝需網路下載開發套件；正式網站已將 React 一起打包。任意靜態 HTTP(S) 伺服器可提供 `dist/`，不可直接以 `file://` 開啟。

## GitHub Pages 發布與版本維護

### 目前部署方式

| 項目 | 設定 |
| --- | --- |
| 原始碼分支 | `main` |
| 網站發布分支 | `gh-pages` |
| Pages 來源 | Deploy from a branch → `gh-pages` → `/(root)` |
| 網站檔案位置 | 將 `main` 的 `dist/` 內容放到 `gh-pages` 根目錄，並保留 `.nojekyll`。 |
| 公開網址 | https://a5029751.github.io/blue-ledger/ |

目前未設定從 `main` 自動同步到 `gh-pages` 的自訂工作流程；需同步發布檔案，再確認 GitHub 內建 Pages 發布結果。專案使用相對資源路徑，支援 `/blue-ledger/` 子路徑。

### 程式更新發布順序

1. 在 `src/` 修改 React 元件或記帳邏輯，執行 `pnpm test` 與必要瀏覽器檢查。
2. 更新 `src/update.js` 的 `RELEASE`（版本號、遞增的 build、日期）、`package.json` 版本及根目錄 `index.html` 的 `pocketa-build`。
3. 執行 `pnpm build`。建置自動產生 `dist/version.json`、`dist/sw.js`、`.nojekyll`，並以內容雜湊處理 JS / CSS 快取；不再手動遞增資源網址參數。
4. 更新第四頁版本說明、README 與必要的 QA 紀錄。
5. 將來源、鎖定檔及建置產物提交到 `main`，將完整 `dist/` 同步到 `gh-pages` 根目錄；不可只發布 `version.json`。
6. 等待 Pages 發布成功，檢查網站四頁、帳目相容性與第四頁更新按鈕。

執行中的網站版本以 `src/update.js` 的 `RELEASE` 為來源；版本檔及離線清單由建置自動同步。帳本支援 version 1 與 version 2，與 App 的版本號無關；version 2 可精確保存字串大額。僅修改 README 時不需增加 App 版本。
